# IndexedDB API

## 概述

一文入门IndexedDB

随着浏览器功能的不断增强和完善，越来越多的网站开始考虑，将大量数据存储在本地，以实现减少对服务器的请求压力，直接从本地获取数据。

可现有的web 存储方案局限性都太大，无法瞒住大数据的永久存储。

| **存储方案**                  | Cookie                                                       | LocalStorage                                                 | SessionStorage                                               |
| ----------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 存储容量                      | 约 4KB                                                       | 约 5MB~10M                                                   | 约 5MB~10M                                                   |
| 存储位置                      | 浏览器 + 随请求发给后端                                      | 浏览器本地                                                   | 浏览器本地                                                   |
| 持久化                        | 可设置过期 / 会话级                                          | 永久持久化                                                   | 标签页关闭即清空                                             |
| 能否存对象 / 二进制           | 只能存字符串                                                 | 仅字符串（需 JSON 序列化）                                   | 仅字符串                                                     |
| 同步 / 异步                   | 同步                                                         | 同步阻塞                                                     | 同步阻塞                                                     |
| 跨域隔离                      | 同域 + 子域可控                                              | 严格同域                                                     | 严格同域、隔离不同标签                                       |
| 核心特点                      | 自动随 HTTP 请求携带、服务端可读写                           | 简单键值、永久不丢、API 极简                                 | 会话级临时存储、隔离标签页                                   |
| 原生局限性                    | 容量极小、明文不安全、有域名限制、每次请求冗余上传           | 容量小、同步阻塞主线程、只能字符串、无过期、无索引无查询     | 生命周期短、同 localStorage 所有短板、不能跨标签共享         |
| **相比 IndexedDB 的核心劣势** | 容量太小、无查询能力、不能存复杂数据、无事务、无法批量操作、性能差 | 同步卡顿、不支持事务 / 索引 / 范围查询、不能存二进制、大数据量性能拉胯、无游标遍历 | 和 LocalStorage 一样，还多了**不能持久、标签销毁就丢**，完全不适合长期本地数据库场景 |

在这种情况下`IndexedDB`应运而生。

`IndexedDB`是一种底层 API，用于在客户端存储大量的结构化数据（也包括文件/二进制大型对象（blob））。该 API 使用索引实现对数据的高性能搜索。虽然 [Web 存储](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Storage_API)在存储较少量的数据很有用，但对于存储更大量的结构化数据来说力不从心。

`IndexedDB`是一个事务型数据库系统，类似于基于 SQL 的关系型数据库管理系统（RDBMS）。然而，不像 RDBMS 使用固定列表，`IndexedDB`是一个基于 JavaScript 的面向对象数据库。`IndexedDB`允许你存储和检索用**键**索引的对象；可以存储[结构化克隆算法](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Workers_API/Structured_clone_algorithm)支持的任何对象。你只需要指定数据库模式，打开与数据库的连接，然后检索和更新一系列**事务**。

理论上讲，`IndexedDB`的容量没有上线，它取决于用户设备本身的磁盘空间。他还能提供查找接口还能建立索引。就数据库类型而言，`IndexedDB`不属于关系型数据库（不支持SQL查询语句），更接近NoSQL数据库。

`Indexed`具有以下特点：

1. **键值对存储：**采用对象仓库存放数据。对象仓库中，数据以==键值对==的形式保存，每一条数据记录都有对应的主键，主键是独一无二的，不能有重复，否则会抛出错误。
2. **异步：**操作时不会锁死浏览器，这和`LocalStorage`形成鲜明对比，后者是同步的。可以防止在大规模数据操作时，出现拖慢浏览器运行的表现。
3. **支持事务：**支持事务，这意味着在执行一系列操作时，有一步出现错误，数据库可以回滚到之前的状态。
4. **同源策略：**受到同源策略限制，每个数据库都对应创建他的域名，网页只能访问自身域名下的数据库，不能跨域访问。
5. **存储空间大：**理论上没有上线，一般不少于250M。
6. **支持二进制存储：**不仅可以存储字符串，还可以存储二进制数据（`ArrayBuffer`对象和`Blob`对象）。

## 基本概念

`IndexedDB`是个比较复杂的API，它涉及了很多概念，学习它其实就是学习他的各种方法。它将各种实体都抽象成了对象接口。

- **数据库：** `IDBDatabase`对象
- **对象仓库：** `IDBObjectStore`对象
- **索引：** `IDBIndex`对象
- **事务：** `IDBIransaction`对象
- **操作请求：** `IDBRequest`对象
- **指针** `IDBCursor`对象
- **主键集合：** `IDBKeyRange`对象

概念解释

#### 数据库

数据库是一系列相关数据的容器，每月域名都可以新建任意多个数据库。

`IndexedDB`有版本的概念，同一时刻只能有一个版本的数据库纯在，如果要修改数据结构（修改删除表结构，删除索引和主键）。

#### 对象仓库

每个数据可都包含若干个对象仓库，他们相当于关系型数据库中的表。

#### 数据记录

对象仓库存储的是数据记录。每条记录类似于关系型数据库的行，但是只有主键和数据体两部分。主键用来建立默认的索引，必须是不同的否则会报错。主键可以是数据记录里的一个属性，也可以指定为一个递增的整数编号.

```js
{ id: 1, text: "你好啊，李银河" }
```

上面的对象中，id属性可以当做主键。

数据体可以是任意数据类型，不限于对象。

#### 索引

为了加速数据的检索，可以在对象仓库里面，为了不同的属性建立索引。

#### 事务

数据记录的读写和删改，都要通过事务实现，事务可以实现回滚操作，操作错误或需要中断操作时，可以将数据库回滚到操作前的状态。
