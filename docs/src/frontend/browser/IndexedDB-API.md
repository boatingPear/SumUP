# IndexedDB API

## 概述

随着浏览器功能的不断增强和完善，越来越多的网站开始考虑，将大量数据存储在本地，以实现减少对服务器的请求压力，直接从本地获取数据。

可现有的web 存储方案局限性都太大，无法瞒住大数据的永久存储。

| 存储方案                       | 存储容量         | 存储位置                | 持久化              | 能否存对象 / 二进制        | 同步 / 异步 | 跨域隔离               | 核心特点                               | 原生局限性                                                 | **相比 IndexedDB 的核心劣势**                                |
| ------------------------------ | ---------------- | ----------------------- | ------------------- | -------------------------- | ----------- | ---------------------- | -------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| **Cookie**                     | 约 4KB           | 浏览器 + 随请求发给后端 | 可设置过期 / 会话级 | 只能存字符串               | 同步        | 同域 + 子域可控        | 自动随 HTTP 请求携带、服务端可读写     | 容量极小、明文不安全、有域名限制、每次请求冗余上传         | 容量太小、无查询能力、不能存复杂数据、无事务、无法批量操作、性能差 |
| **LocalStorage**               | 约 5MB           | 浏览器本地              | 永久持久化          | 仅字符串（需 JSON 序列化） | 同步阻塞    | 严格同域               | 简单键值、永久不丢、API 极简           | 容量小、同步阻塞主线程、只能字符串、无过期、无索引无查询   | 同步卡顿、不支持事务 / 索引 / 范围查询、不能存二进制、大数据量性能拉胯、无游标遍历 |
| **SessionStorage**             | 约 5MB           | 浏览器本地              | 标签页关闭即清空    | 仅字符串                   | 同步阻塞    | 严格同域、隔离不同标签 | 会话级临时存储、隔离标签页             | 生命周期短、同 localStorage 所有短板、不能跨标签共享       | 和 LocalStorage 一样，还多了**不能持久、标签销毁就丢**，完全不适合长期本地数据库场景 |
| **Cache Storage（HTTP 缓存）** | 较大（几十 MB+） | 浏览器缓存池            | 可手动管理          | 二进制 / 文件 / 静态资源   | 异步        | 同域                   | 专门存静态资源、请求缓存、PWA 离线可用 | 只能存**Response / 请求资源**，不适合存业务结构化数据      | 不能存普通业务对象、无索引查询、不适合做业务数据库，只能存静态文件 |
| **File System Access API**     | 很大 (磁盘级)    | 本地真实文件            | 永久                | 二进制 / 大文件            | 异步        | 需用户授权             | 直接读写本地文件、操作目录             | 兼容性一般、需要手动授权、有安全沙箱限制、不能做结构化查询 | 无数据库索引 / 事务 / 范围查询、只能文件读写、不适合存列表结构化业务数据 |
